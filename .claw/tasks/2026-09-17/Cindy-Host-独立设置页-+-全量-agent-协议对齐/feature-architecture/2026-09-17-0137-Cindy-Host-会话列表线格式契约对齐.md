# 2026-09-17-0137-Cindy-Host-会话列表线格式契约对齐

## 问题

Cindy 手机端能看到 DSH Host 这台设备并显示在线，但选中该设备后列表为空（首页空态文案「还没有任务」）。Host 侧 `local-db:sessions:list` 返回 `ok:true` 且带 1 条数据，所以问题不在「有没有数据」，而在**这条数据是不是通道合同规定的形状**。

**根因（已实测复现，非推断）**：Host 在 `local-db:sessions:list` 上返回的是 **`RemoteSessionListItem[]`（外层包了一层 `session` 的视图模型）**，而该通道的合同是**扁平的 `RemoteSession[]`（`sessionToCamel` 行）**。手机端不做解包，直接把整个外层对象当作 `RemoteSession` 存进 store，于是所有身份与筛选字段（`id`、`status`、`deviceLinkDeviceId`、`workingDir`）都变成 `undefined`，行在共享筛选层被静默丢弃。

用 Cindy 自己的代码把 Host 实际返回的那一行喂进手机自己的渲染管线（`tools/probe-list-shape.ts` / `probe-list-shape2.ts`，用 Cindy 自己的 tsx 运行）：

| 输入形状 | 首页（已选该设备，statusFilter=active） | 首页（all） | 设备详情页（active） | 详情页（all） |
| --- | --- | --- | --- | --- |
| **A. 当前实际返回（带 `session` 外壳）** | `projects:0 chats:0 pinned:0`，overview.all=0 | 同样 0 | **0 行** | 1 行（垃圾行） |
| **B. 扁平（桌面端合同）** | `projects:1`，overview.all=1，devices=1 | 1 行 | **1 行** | 1 行 |

同一探针读取手机会用到的身份字段：

```
wrapped: deviceLinkDeviceId=null  id=null  status=null
flat:    deviceLinkDeviceId="<host-device>-…"  id="session-32859d1e-…"  status="active"
```

注意探针 A 里 `deviceFilters` **仍然列出了该设备且 `available:true`**，同时 `overview.devices:0`、行数为 0 —— 这正是用户观测到的「设备在线可见、但一条任务都没有」的精确形态。

**丢弃发生在哪一层**（三处独立、互相叠加，因此任何筛选组合都渲染不出来）：

1. `recomputeSessions` 以 `session.id` 为去重键，外壳行的 `id` 是 `undefined`，所有行塌成同一条 `undefined` 键（`apps/mobile/src/session/remoteSessionStore.ts:1461-1477`）。
2. 状态筛选：首页与详情页的默认 `statusFilter` 都是 `'active'`，判据是 `session.status === filter`；`undefined !== 'active'` → 丢弃（`packages/maker-shared/src/sessionList.ts:701`、`packages/maker-shared/src/mobileHome.ts:517`、默认值 `mobileHome.ts:145`、详情页默认值 `app/devices/[deviceId].tsx:1379-1390`）。
3. 设备筛选：两个界面都按 `canonicalDeviceId ?? deviceLinkDeviceId === deviceId` 过滤，外壳行两者皆 `undefined` → 丢弃（首页 `mobileHome.ts:466-468,500-502`；详情页 `app/devices/[deviceId].tsx:179-184`）。

**「早期能看到一条」是未验证的假设**：本仓库没有 git 历史（`git log` 返回 `not a repository`），无法比对旧版本。最可能是当时 Host 侧映射器曾直接返回扁平行，或该行来自旧构建写入的手机首页快照缓存。可证伪的判别器：若当时那一条出现在「对话」分组、且标题显示为会话 id 一类的编码串，则与「外壳行被当作 dialogue（`workingDir` 为 `undefined` → `isDialogueSession` 为真）渲染」一致；若出现在某个项目分组下，则说明当时喂进去的是扁平行。**标注为假设。**

## 边界与不变量

- **线格式的唯一 owner 是 Cindy 桌面端 main**（`local-db:sessions:list` → `mergedRows.map(r => sessionToCamel(...))`，`apps/desktop/src/main/localDb/ipc/sessions.ts:1258-1270`；形状定义 `apps/desktop/src/main/localDb/mapper.ts:208-278`）。Host 是**镜像者**，不得自创形状；手机端 `remoteSessionStore` 是唯一消费者。
- `RemoteSessionListItem` 是**视图模型，不是线格式**。它由共享构造器在内部产出（`sessionList.ts:190` 的 `toRemoteSessionListItem(...)`、`mobileHome.ts:174`），**只可能由 Host/桌面端产出的搜索结果**（`local-db:conversations:search`，`apps/desktop/src/main/localDb/ipc/search.ts:21-48`，手机侧消费见 `apps/mobile/src/session/conversationSearch.ts:273-307`）才是外壳形状。**不变量：`local-db:sessions:list` / `sessions:get` 永不返回外壳形状。**
- **设备归属不变量**：手机可见的每一行，其 `deviceLinkDeviceId` / `deviceLinkDeviceName` 必须在 **session 对象顶层**。
- **状态不变量**：`status` 必须在顶层且属于 `'active' | 'archived' | 'deleted'`（`apps/mobile/src/session/types.ts:7,65`）。
- 手机端**不做形状校验、不做解包**：`remoteSessionStore.setDeviceSessions` 只做 `stamp` 与去重键运算（`remoteSessionStore.ts:3191-3192`），调用点只有 `Array.isArray(list) ? list : []`（`[deviceId].tsx:292`、`index.tsx:777`）。**不变量：错误形状不会报错，只会静默变空** —— 因此形状必须由 Host 侧的回归测试守住，不能依赖端到端现象。
- **范围外 channel fail-closed 返回 `CHANNEL_NOT_ALLOWED` 是正确决策，且经查不是本问题成因**（`src/cindy-channels.js:10-15,186-187`）：手机端对这四类 channel 全部有显式降级路径 —— `maker:remote-resources:manifest` → `CHANNEL_NOT_ALLOWED` 判定为「不支持」返回 `null`（`apps/mobile/src/device-link/remoteResources.ts:215-236`）；`maker:get-new-maker-defaults` → 缺字段/形状异常返回 `null`（`apps/mobile/src/session/newSessionWorktree.ts:268`）；`maker:schedule:list` 族 → `loadSharedSessionScheduleIndex` 的 `.catch` 落成空 Map（`app/devices/[deviceId].tsx:300-309`）；`sidebar-settings:get-project-order` → 显式按「channel 缺失」降级为 `activity` 排序（`packages/maker-shared/src/projectOrderSync.ts:234-236`）。**保留该决策。**
- 非目标（本轮不实现）：orca、remote-desktop、media、voice、schedule、worktree 族；不改 DSH Web shell 与用户主 profile。

## 新增或改变的概念、唯一 owner 与数据流

**要删除的概念**：`RemoteSessionListItem` 作为 Host 的会话列表出口形状。Host 当前把 `{session: {...}}` 外壳当作线格式写入 `src/cindy-session-row.js:50-74`，其文件头注释（`src/cindy-session-row.js:1-13`）声称「`mobileMakerTransport.listSessions()` 期望 `RemoteSessionListItem[]`」—— 该 API 在 Cindy 仓库中**不存在**（全仓 `listSessions` 检索无此方法；手机侧真实调用点是 `app/devices/*.tsx` 直接 invoke 并把结果原样交给 store）。这是一条无法被源码支撑的自造合同，是本次形状写错的直接来源。

**唯一 owner 划分**：

| 概念 | 唯一 owner | 说明 |
| --- | --- | --- |
| `RemoteSession`（线格式） | Cindy 桌面端 main（`localDb/mapper.ts:208`） | Host 只镜像，不自创 |
| DSH 会话 → Cindy `RemoteSession` 的折叠 | Host `src/cindy-session-row.js`（`toCindySessionRow`） | 扁平出口，顶层携带身份与状态 |
| `local-db:sessions:list` / `sessions:get` 应答形状 | Host `src/cindy-channels.js:112-115,140-150` | 直接返回扁平数组/单行 |
| 会话列表的客户端真相 | 手机 `remoteSessionStore`（`setDeviceSessions`） | 全量权威对账，push 只是增量 |
| `RemoteSessionListItem` | 共享构造器内部（`maker-shared/sessionList.ts`） | Host 不得产出 |

**数据流（修复后）**：DSH 会话读模型 → `toCindySessionRow` 折叠为扁平 `RemoteSession`（顶层 `id`/`status`/`deviceLinkDeviceId`/`deviceLinkDeviceName`/`workingDir`）→ `invokeResult` 原样返回数组 → 手机 `setDeviceSessions` 按 `session.id` 分片 → `recomputeSessions` 归一化身份 → 首页 `buildMobileHomePresentation` / 详情页 `buildRemoteSessionSections` 各自过滤并**内部**构造 `RemoteSessionListItem` 渲染。

**push 不是渲染前置条件**（回答任务问题 3）：`setDeviceSessions` 对整表做权威替换（`remoteSessionStore.ts:3191-3259`），首页与详情页每次 `sessions:list` 成功后都会调用它；`local-db:sessions:created` / `patched` / `activity` 只承载增量与实时活动（`packages/device-link/src/topics.ts:141-153`）。缺 push 表现为「不实时」，**不会**表现为空列表。

**没有设备能力/在线态前置门控**（回答任务问题 4）：`buildMobileHomePresentation` 的输入只有 `sessions` + `devices` + `statusFilter`（`mobileHome.ts:116-148`）；`maker:get-capabilities` / `maker:list-available-agents` 只被新建会话的 harness 选择器消费。设备在线态只影响 `deviceFilters[].available`，而探针 A 显示该设备 `available:true` 时列表依然为空 —— 门控假设可排除。

## 推荐决策、关键理由与一个关键失败路径

**D1（必须，根因）：`local-db:sessions:list` 返回扁平 `RemoteSession[]`。**
把 `toCindySessionListRow` 的 `session` 外壳去掉，让 `id`/`title`/`createdAt`/`updatedAt`/`status`/`agentKind`/`model`/`workingDir`/`workspaceKind`/`preview`/`_count`/`running`/`deviceLinkDeviceId`/`deviceLinkDeviceName` 直接位于行顶层；`RemoteSessionListItem` 独有的 `subtitle`/`detail`/`messagePreview`/`liveActivity`/`lastActivityAt`/`pendingInteractionCount`/`scheduleInfo`/`worktreeLabel` 全部移出线格式（`title` 例外：`RemoteSession.title` 本就存在）。
理由：桌面端合同即扁平（`sessions.ts:1258-1270`、`mapper.ts:230-279`）；手机端真实调用点原样入库、无解包（`[deviceId].tsx:283,292`、`index.tsx:737,777-783`）；手机仓库自带参考被控端亦返回扁平（`apps/mobile/scripts/mock-device-link-host.mjs:245-246,1195-1211`）；探针 A/B 对照证明扁平即渲染、外壳即空。
锚点：`src/cindy-session-row.js:43-89`、`src/cindy-channels.js:112-115,140-142`。

**D2（必须）：`local-db:sessions:get` 返回同一条扁平行。**
当前它从同一个外壳数组里 `find` 后整行返回（`src/cindy-channels.js:144-150`），因此同源缺陷；手机打开会话时走 `maker.getSession` → `local-db:sessions:get`（`mobileMakerTransport.ts:681`）。修 D1 后自然一致，但需断言二者出口同源，避免再分叉。
锚点：`src/cindy-channels.js:144-150`；桌面端对应实现 `apps/desktop/src/main/localDb/ipc/sessions.ts:1655`。

**D3（必须，同源缺陷）：`maker:list-active` 返回 `[{sessionId, isTurnRunning}]`。**
这是第三种形状，既不是 `RemoteSession` 也不是外壳。手机 `setActiveSessionSnapshots` 只读顶层的 `sessionId` + 布尔 `isTurnRunning`（`remoteSessionStore.ts:4080-4087`），当前 Host 返回外壳行（`session.running`）→ 全部被跳过 → 静默 no-op（不阻塞列表，但运行态徽标永远不亮）。桌面端合同见 `apps/desktop/src/main/maker-ipc/register.ts:15419-15425` 与 `apps/desktop/src/main/device-link/dispatch.ts:539-545`。
锚点：`src/cindy-channels.js:159-164`。

**D4（保留）：范围外 channel 继续 fail-closed。**
理由见「边界与不变量」中逐条降级证据。任务问题 2 的答案是：**缺这些 channel 不会导致渲染为空**，它们各自的缺失路径在手机端都被显式处理。用接受后失败来「假装支持」反而会让手机显示坏掉的功能。

**D5（必须）：把形状变成可回归的合同，而不是靠端到端眼看。**
理由：错误形状不报错、只变空（`setDeviceSessions` 无校验），且 Host 是唯一的适配层 —— 只有 Host 侧测试能在无手机的情况下守住它。

**关键失败路径（必须在实现时防住）**：只把外壳去掉、却把 `deviceLinkDeviceId`/`deviceLinkDeviceName` 留在 `session` 子对象或遗漏 `status`，会得到**更隐蔽的半失效**：详情页在 `statusFilter=all` 下可能仍显示行（`undefined !== 'deleted'` 通过，与探针 A 的 `detail_all:1` 同形），而首页在选中设备时永远为空（设备键缺失），默认 `active` 下两个界面都为空。表现出来就是「有时能看到、切个筛选就没了」，比现在更难定位。防线是 D5 的断言必须同时覆盖 `status`、`deviceLinkDeviceId`、`deviceLinkDeviceName`、`id` 四个顶层字段，而不只是行数。
