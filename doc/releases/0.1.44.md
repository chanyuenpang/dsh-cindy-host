# 0.1.44：原生会话与列表同步

日期：2026-11-17。正式实现基于已在用户环境加载并确认目标任务可见、连续刷新的 `0.1.44-local.6`，不混入后续实验逻辑。沿用 `main`，不新建分支或 worktree。

## 改动与身份

- 原生 assistant/control/history 展示投影同步，pending inbox 更新不依赖 assistant 输出；详情历史与 work-line 更新保持原生事实归属。
- 列表统一使用可丢弃的 core 投影；已知行脏通知按身份精确修复，集合/全局失效、规范化 view 和辅助证据使用独立围栏，避免无业务字段变化的请求头使整个目录读取饥饿。
- 最新窗口/状态/置顶选择先于可选标量证据读取；交付受字节/来源/授权/订阅约束，支持已声明的gzip/tag，不声称delta或业务ACK。
- 原生 retry 保持策略/终态所有权，scheduled/started 不生成历史消息；有限TRANSPORT重试仅投影为现有非终态重连展示。
- 包与运行时身份正式为 `0.1.44`；Cindy握手仍 `0.1.82`。DSH精确peer列表与0.1.43相同，本次目标SDK为 `0.2.2-rc.3`，不泛化到未来版本。
- 核对已验收tarball的94个 `src`/`lib` 文件：正式包除版本常量文件外其余93个运行文件逐字节相同。没有Cindy源码修改。

## 必须保留的范围与限制

- **旧格式发现范围：** 仅原生明确报告 `migration-required` 的会话暂不进入发现列表。源日志不删除，直接读取保留原生真实结果/错误；原生迁移为当前格式后重新发现。大量旧会话可能因此暂时不可见，不能把它写成自动修好历史迁移。
- 仍保留5秒单次读取预算；大库首次冷覆盖曾实测约16–19秒。已加载local.6的同一进程在最终恢复确认前仍记录过5次真实预算超时，阶段原因未完整分解。
- 用户指定目标任务可见、连续刷新正常及三次202行后台成功是有限的当前恢复验收，不等于任意规模/负载下零超时。重新登录与恢复的因果关系没有单独证明，不应要求反复登录或清缓存掩盖问题。
- 泛化空payload reseed仍默认关闭，需目标消费者兼容证据才允许启用；未实现可靠业务传输或delta。
